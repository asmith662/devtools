# Increment 32: structural expansion round one (Graph-1)

**State: completed development breadth baseline using one prospectively frozen probability sample.** Candidate mechanics, sampling, blinded decisions, and the development result are frozen. Confirmation remains sealed.

## Question and boundary

Graph-1 tests whether exactly one additional typed structural edge from the resources already reached by the four completed direct structural experiments exposes useful parent-snapshot resources outside the complete saved direct evidence union. This is structural expansion **round 1**, usually two structural edges from an original lexical seed. It is not a repeat of the direct seed-to-candidate experiments. The experiment uses exactly 24 frozen development InformationNeeds and their historical parent snapshots; confirmation remains sealed.

The frontier is the union of saved direct Imports, References/direct Calls, immediate package containment, and exact mirrored source/test path candidates from canonical lexical top-five seeds. Saved first-edge native supports identify each original seed and first relation. The saved candidate lists do **not** supply second-edge adjacency. For every parent snapshot, mechanics reconstructs the underlying four relation families and projects all supported directions incident to arbitrary frontier resources. Lexical seeds are never expanded as frontier resources. Newly reached resources are never expanded again.

Each novel candidate is one case/InformationNeed/parent-snapshot/resource identity regardless of path multiplicity. Distinct typed support paths retain the original seed, frontier resource, both relation families and directions, native relation supports, snapshot identity, and final candidate. Direct-call is a specialization tag on one reference occurrence, not a separate parallel edge. Exact mirrored paths assert correspondence only; they do not assert testing, exercise, coverage, or validation. Import relationships do not assert runtime import execution.

The primary candidate population excludes all five saved positive lexical universes and the four completed direct structural candidate populations. Returns to the originating seed are rejected. Landings in the direct union are retained only as aggregate overlap diagnostics and never sent for new judgment. No pruning, top-N, graph scoring, configurable depth, graph framework, or production change is present.

## Prospective sampling and blinded outcomes

After candidate mechanics froze, exact development judgment reuse covered **2** of 704 novel pairs: 0 `USEFUL`, 2 `NOT_USEFUL`, and 0 `UNJUDGED`. The other **702** formed the complete unresolved neutral sampling frame. The protocol selected a **simple random sample without replacement** of 128 neutral target identities, using `random.Random(320128).sample` on lexicographically sorted `(neutral_case_id, neutral_resource_id)` tuples. The fixed seed, exact selected and unselected identities, source neutral input hash, and sample input were persisted and verified **before** usefulness review. No relation, path, rank, resource type, multiplicity, or prior-family property entered selection. The sample did not alter the complete 704-pair candidate surface.

The sampled neutral input contains only opaque identities, the frozen InformationNeed and parent snapshot, resource address, and parent-snapshot content. It contains no structural origin, path, direction, multiplicity, lexical rank, prior-family membership, score, or usefulness hint. Exactly the 128 selected targets were adjudicated from this input. All decisions, rationales, and three-state target coverage were frozen before joining Graph-1 provenance.

## Architecture interpretation

Repository relation facts, purpose-relative traversal, and retrieval usefulness remain separate. Imports is already a production Repository Intelligence relation. Repeated use of bounded References/direct Calls and immediate package membership creates production-RI pressure, but this experiment does not promote them. Mirrored-path correspondence remains a narrow experimental fact. The one-round typed path records do not justify a universal graph or a production traversal API.

Typed paths could later help Context explain why a resource was retrieved, disclose an exact import or reference occurrence, summarize a short qualified structural chain, offer neighboring resources progressively, and distinguish direct from structurally inferred relevance. Those Context-compilation uses are plausible but untested here.

The next breadth step is **Graph-2 investigation/design**. Its frontier must be selected from the complete frozen Graph-1 surface by outcome-independent semantics; expanding only sampled `USEFUL` resources would contaminate traversal with partial judgments. Family-specific pruning, ranking, path weighting, and deeper refinements remain parked.
