# Experimental selective mechanism routing

This non-installable package composes existing native contracts. Dependencies
flow `experiments -> devtools`; production imports none of this package.

`RoutingBasis` is a permission wrapper around the existing experimental
`InformationNeed`, native obligation, hint and provenance. It does not introduce
another AcquisitionIntent fact type and does not consume Case 0011's need set.
Fresh caller-authored purposes use the explicit grammar `Inspect existing ...`,
`Introduce new ...`, or `Understand ...`. Unknown grammar fails authoring rather
than guessing. These roles are mutually understandable task annotations, not
gold labels. A new destination can still require repository context; its entire
obligation query remains active.

A invokes no exact mechanism. B admits every supported explicit hint. C admits
only INSPECT_EXISTING hints. Unsupported owners retain lexical fallback.
Address/module/direct function/direct class/direct method requests delegate to
U2's native grounding adapters. Exact declaration acquisition is the existing
direct-source path, not runtime binding inference. C does not predict whether a
selected target is REQUIRED or a bottleneck. Any useful B route skipped by C is
reported later; it can invalidate the selective-value gate.

`composition.compose` accepts captured outcomes and delegates candidate/frame,
rank, score and contribution preservation to U2 presentation. It executes no
mechanism. Stage A has no treatment runner. Per-arm plans and exact request-set
checks prevent accidental arm contamination; native outcomes may naturally be
equal across arms, but future timing/execution records must remain separate.

This is a deterministic policy hypothesis, not production routing, universal
repository graphs, relevance, witness acceptance, sufficiency or a sequential
search policy. Maintainer review must challenge the role annotations and full
task/obligation matrix before any prospective execution.
