# U1 — manual information-need decomposition

Frozen before treatment execution. The hypothesis is that bounded manually
authored repository-information needs and simple literal queries reduce depth
and unnecessary burden versus whole-task/current-obligation formulation while
preserving REQUIRED reach. Primary target INFORMATION_NEED_OBLIGATION_FAILURE,
specifically inadequate retrieval-oriented formulation under a valid obligation;
secondary target RANKING_DISCRIMINATION_FAILURE. Mixed intent/query dilution is
a possible diagnosed contributor, not a new failure enum or search policy.

Original task.txt is exact UTF-8 input including terminal LF. authoring.json and
AUTHORING.md were sealed before production/capture/resource inspection. Nine
mandatory caller obligations, eighteen manual needs and one initial query per
need are projected, not generated. Exact literal hints are recorded but not
routed. Arm A is the whole task; B has one native ObligationLexicalQuery per
obligation; C independently executes each need query. No fusion or reranking.
All use native production canonical BM25 (1.2, 0.75, 0.25), the same full corpus,
eligibility and ties; no synonym expansion, weights, feedback or reformulation.

The frame is a broad Git export at starting 85f9f088c5be2afb7861803ee1a96ac7db0448a2,
using established Case 0009 eligibility. Experiments, experiment tests, research/
reports, ledger and confirmation/reserve are excluded. New U1 metadata and
course-correction documentation are not in this starting frame. Source/test/
docs/config resources are included by role, never by query or gold.

Stage A freezes treatment, native identities/content/frame, source/runtime hashes,
immutable Stage A trace/review and decision semantics. All execution code must be
committed unchanged before exclusive Stage B marker creation. No retries or
overwrites; ambiguous interrupted execution must stop for reconciliation, never
rescore. Native queries run once with complete positive sets. Cost includes
native query analysis/scoring and native filename index creation; content index
build and R1.5 diagnostics are reported separately. No second scoring for replay.

Decision details, metrics, alternative/coverage rules and outcome precedence
are frozen verbatim in treatment.json decision_rule. Safety compares exact B/C
REQUIRED resource/cell/unit sets. Required-unit need completeness is exactly
100%, not post-hoc nearly-all. Improvement requires at least 20% in C's unique
completion-prefix union OR unnecessary prefix occurrences versus B, with the
other metric no worse than 1.05x B. Every mandatory obligation's C unique prefix
union must be at most 1.25x its B accepted-alternative depth. Extra query count
and timing are openly reported, not automatic rejection gates. No scalar winner.

Independent C.5 mapping assigns every unit to all responsible frozen needs before
joining outcomes; no best-performing need is chosen post-hoc. Query completion
uses resources supporting assigned units in one valid complete gold alternative.
Null remains a miss, never an inflated rank. C alternatives tie by prefix union,
occurrences, maximum need depth and alternative identity. B ties by depth and
identity. Every need's zero/positive/missing responsibility is reported. Costs of
zero-unit needs remain visible even when their completion prefix is zero.

Exact outcomes: INFORMATION_NEED_DECOMPOSITION_SUPPORTED;
COMPLEMENTARY_BUT_NOT_CLEARLY_BETTER; NO_MATERIAL_VALUE;
INFORMATION_NEED_AUTHORING_DEFECT; EXPERIMENTAL_CONTRACT_DEFECT.
Contract defects stop first; omitted required units or a misformulated responsible
need constitute authoring defect. All prospective gates constitute support;
otherwise reach-safe benefit/rescue is complementary; otherwise no material value.
Incomplete baseline ratios cannot satisfy the quantitative gate.

trace.json/TRACE.md expose every TASK → OBLIGATION → INFORMATION_NEED → QUERY →
ROUTE → RESULT. Stage A snapshot is immutable; B adds unjudged results. Gold,
required units and failure attribution wait for D. Full rows/aggregate field
contributions are in trace.json, complete exact term evidence is hash-bound in
results.json.gz. REVIEW documents print every input, analyzer terms, top-five
inspection rows, DF/IDF, footprint, duplicates and costs. Yield is UNKNOWN until
independent gold; footprint alone does not establish dilution or a failure.

Human observation is NOT gold. MANUAL_AUDIT remains separate. Fresh Stage C sees
only task/obligations/resource contents; never needs, queries or results. C.5 is
a separate fresh reviewer after committed C, with needs and gold but no queries,
arms or results. Only D may join and explain GOOD_NEED/BAD_QUERY, missing or
redundant needs, dilution, ranking, representation and possible vocabulary mismatch.
STOP after Stage B and a double-built six-input sterile Stage C packet. Do not
adjudicate C, build C.5 or perform D. Production and Localization remain unchanged;
U2/U3 future, true BM25F mandatory, no semantic-resolution effectiveness work.
