# Historical development population extension

This is a treatment-independent historical-replay DEVELOPMENT population.
The parent Git commit/tree is the untouched evaluation frame; the exact original
commit message is the task. No obligation, query, structural mechanism, ranking
rule or effectiveness gate is designed here. Eventual dogfood case numbering is
reserved until a separately authorized Stage A; population-local identities are
`historical-development-001`, etc., in deterministic prospective use order.

**The child implementation is not relevance gold.** A developer's changed files
do not establish which parent-frame resources are REQUIRED, HELPFUL_ONLY or
UNNECESSARY. Independent treatment-blind semantic gold follows frozen treatment
capture. Implementation comparison or changed-file recall may be used only after
the semantic result is frozen, as separate external-validity diagnostics.

## Source and cutoff

The starting repository is `07ca25ad2c37fae5106597ba2f49ce2b40372a30`. Enumeration
uses first-parent committed history, without reflogs or historical code execution.
The canonical current population program first publishes Increment 25's freeze
at `e0a6d817d7a155f5f77241902e4710c8b6b2807b`; its parent
`dc0ba53182d5d90a9db1b0783f73446c412d5850` is the conservative scope tip.
All 122 preceding first-parent commits are inventoried. Starting history has 284
first-parent commits. Earlier retrieval experiments/benchmarks are individually
excluded; this anchor does not claim they did not exist.

A forward expansion to the entire starting first-parent history was authorized
only if the preferred scope had fewer than eight eligible episodes, under the
same exclusions/thresholds. It was unnecessary: 15 qualify, so all 15 are retained
under the target16/minimum8 policy. No window, parameter or seed was rerolled.

Size limits were frozen after aggregate metadata inspection and before subject
review: at least one production source file, at most 24 total changed files,
at most 10 production files, at most 2,000 production/test changed lines, and no
binary production/test change. Before the anchor, 75 single-parent production
episodes have medians 9 total files / 3 production files / 413 changed lines and
p90 23 / 10 / 1,723. Rounded scale limits exclude giant migrations without using
task relevance or predicted structural usefulness.

Eligibility also requires a concrete engineering obligation in unchanged commit
text, substantive production work and no evaluation-infrastructure purpose.
Opaque/mechanical subjects reject. Two fix subjects did not identify their defect
or corrected behavior; they reject without semantic patch inspection. Commit-
message-only authority is used; no linked work-item augmentation or synthetic
task wording is introduced. Provider adaptation tasks do not require secrets or
inaccessible organizational state merely to understand their stated capability;
future implementation validation remains distinct from retrieval evaluation.

All 38 previous population identities, including held-out identities, are excluded
before task-message review. Their messages are withheld in the inventory; only
IDs and mechanical object bindings/counts are retained. Prior development/dogfood
task text is used for duplicate checks without gold or retrieval outputs. Exact
normalized task duplicate collapse is deterministic; no duplicate group remains.
All 16 prior dogfood task sources are separately hash-bound in
`prior_task_exclusions.json`. Case 0001/0002 shared preparation-record field names
were incidentally exposed while locating task text; result values were not
inspected or used. The access record distinguishes this from an output-based
selection analysis. No confirmation/reserve task body or gold was opened.

## Public task versus restricted implementation

`selected_next_case.json` and each task in `population_freeze.json` expose only
exact task text/source hashes, parent commit/tree/frame and selection position.
They omit child identity, path lists, patch content, changed tests, inferred
symbols, relevance labels and retrieval information. `candidate_inventory.json`
and `selection_provenance.json` are population-administration records, not future
treatment inputs; they must not be copied into a treatment/adjudication packet.

Everything in `holdout/` is **RESTRICTED UNTIL POST-GOLD / STAGE D**.
Future Stage A/B/C sessions MUST NOT open the child implementation manifest,
child patch/paths or descendants that reveal it. Prefer sterile packets containing
only the selected public task and materialized parent frame. Git is not secret;
this restriction is experimental protocol, not an OS authorization boundary.

Pre-selection construction mechanically read path classes, counts and numstat.
Eligible patch bytes were read only to hash them, never semantically parsed,
displayed or stored as patch text. The captured digest receipt is immutable and
content-addressed. After selection, rebuild consumes that receipt and never
reopens selected patch/path lists. Git validation reads commit/tree metadata only.
It is not a claim that changed files establish semantic correctness or relevance.
Parent-frame absence is established by the parent/child change boundary, not a
new implementation test or retrospective gold inference.

## Determinism and validation

Canonicalize the complete inventory and eligible representatives first. The seed
is SHA256 of the canonical JSON array containing the domain separator, starting
HEAD, history-scope digest, exact original/expanded freeze digests and eligible
inventory digest. Selection keys are SHA256(seed raw bytes + UTF8 candidate ID),
ordered by raw digest bytes then identity. First16, or all8..15, become use order;
item1 is the immediate next case. All seed inputs/results are explicit artifacts.

The builder binds the pre-selection receipt, source-exhaustion audit and local
implementation bytes. VERIFY reconstructs expected bytes, checks Git traversal/
object/parent-tree identities and compares all artifacts. It does not rerun
retrieval, native scientific proof or child implementation. BUILD refuses any
existing output, including a partial publication.
Prior population content identities and exact source blobs, all previous task
source hashes, the unchanged six-file exhaustion audit and mechanical eligibility
bounds are also checked. The receipt is the pre-selection mechanical inspection
record; replay authenticates it rather than inspecting a selected implementation
again. Task sufficiency is a frozen metadata decision, not inferred from a patch.

```text
python -m experiments.development_population.extension_01.historical.builder verify
```

`build` is the one-time publication command and must not replace an existing
freeze. Later scientific stages use sealed normal verification for completed
capture proofs, and deep verification at capture finalization or explicit forensic
boundaries. No Stage B/C/D scientific artifact is generated by this population.
