# Increment 25 — task-population freeze

This experiment investigates **lexically seeded structural expansion**: whether
outgoing one-intermediate imported-member binding expansion from a shared
lexical seed can expose useful resources beyond candidate-volume-matched lexical
widening. It is not structural retrieval independent of lexical retrieval.

`task_population_freeze.json` is a Git-metadata-only freeze of historical
maintenance tasks. It uses each selected commit's parent as the future retrieval
snapshot. Case selection is mechanism-blind: no lexical retrieval, imported-
member resolution, candidate surface, usefulness judgment, or metric has been
generated at this checkpoint.

The freeze uses a fixed seed and assigns eight development cases, sixteen
sealed confirmation cases, and fourteen reserve cases. Development may validate
acquisition, serialization, blinding, and control mechanics only. The matched
lexical control is frozen as protocol intent but has not been executed.
Confirmation may not be inspected by retrieval outcomes until the future
mechanism is frozen after development.

## Development candidate-generation machinery

`run_development.py` now executes all and only the eight development case IDs
derived from the validated freeze. It materializes each task's frozen parent
commit from Git objects into an isolated temporary directory, builds the corpus
from tracked resources beneath the frozen `src` and `tests` roots, and composes
the existing whole-resource lexical pipeline. The shared seed is the first five
positive results from canonical content BM25 plus `0.25 *` filename-stem BM25.

For each seed resource, the development generator evaluates outgoing canonical
imported-member binding resolution and projects only `RESOLVED` function
targets to defining resources. It remains one facade and one hop, excludes seed
resources, deduplicates target resources while retaining every native support,
and preserves unresolved-in-universe, ambiguous, and unsupported diagnostics.
The matched control adds the next `m` positive lexical resources and records
exhaustion explicitly.

The generated `development_candidate_evidence.json` contains candidate-surface
mechanics only. `development_judgment_input.json` separately exposes neutral
parent-snapshot resource identities and content while hiding candidate origin,
lexical rank, structural support, resolution state, and changed-path metadata.
No judgments have been made. The confirmation partition remains sealed; no
confirmation or reserve retrieval outcome is generated by the development-only
CLI. The frozen structural and matched-control rules are unchanged.
