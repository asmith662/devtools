# Coding contracts in active working Context

The resident enrolled Qwen resource is the current default for coding, planning,
research and supervised review. This is model selection for existing consumers,
not a Qwen Agent class, scheduler or promotion to autonomous acceptance review.
Each role owns separate instructions, source scope, conversation and task/episode
notes. Shared weights or KV cache do not share permissions or conclusions.

## Existing coding owner

`RepositoryCodingHost` optionally accepts `working_scope=NoteScope(task,
"coding-worker:" + actor, episode)` and `observe_working`, a checkpoint callback.
The trusted caller binds existing task/actor/episode identities. Omitting these
options preserves historical default behavior; no native assignment is rewritten.

The opted-in host supplies a first system-role instruction, a separate task user
message, the existing inventory/navigation slot and a protected working view.
The procedure asks the coder to inspect a changed producer's annotation,
documented return contract and callers through existing RI/source navigation;
record a compact provisional relationship with exact source quotes; reconsult
it before editing; and repair using precise host-fixed type/behavior diagnostics.
Metadata and retained notes never replace source/edit witnesses.

### Explicit producer/caller witnesses

A trusted caller may pass `contract_sources=(producer, caller, ...)`, using
existing `SourceRangeDisclosureOption` selections from RI/source navigation or
Localization. This is disclosure configuration, not a new relationship graph or
Tool. At most eight distinct, current selections fit one 8,192-byte envelope;
the complete request and token limits still apply. Oversized required evidence
fails closed rather than silently dropping one side of the contract.

The protected `coding_contract_witnesses` user slot contains exact text, native
unit identity, snapshot/content identities, actual ranges, partial-read status
and the selection's purpose. Use purpose to identify the producer, caller and
provisional relationship or uncertainty. These host interpretations are not
verified semantic facts. Public behavior/type checks remain separately declared
in the objective's existing fixed-check plan. Models can reopen missing evidence
through the unchanged source Tools.

These are real host-selected disclosures, retained in the existing source result
and disclosure collections; they do not count as model source-Tool actions.
Projection protects the slot, and current ranges participate in existing edit
witness admission. An admitted edit changes the snapshot: the derived slot then
removes old text and explicitly marks its witnesses stale. Old offsets never
silently rebind to new source. Select fresh units through the existing source
owner, or inspect source again; the immutable initial selection is not refreshed
by a model's assertion. The default empty selection preserves prior requests.

The existing `WORKING_NOTES` assistant-content protocol can accompany an ordinary
native source call. It adds no Tool, model call, editable range or permission.
Note-only prose remains a stop; Tool-shaped prose is never executed.
`WorkingNotes.admit_batch` owns atomic bounded admission for coder and reviewer.
Model fields cannot attest verification. The coding adapter borrows current
snapshot resources and completed disclosure ranges, not a second read ledger.
A matching quotation proves its text, not an interpretation of runtime behavior.

## Bounds, freshness and capture

The entire note envelope fits 8,192 UTF-8 bytes inside existing complete-request
and provider-token limits. The shared selector prioritizes active claims and
reports omitted active sequences. Mandatory scope that cannot fit fails closed;
no budget grows automatically. Current source is labeled `current-source`,
whether baseline or admitted candidate. Archived evidence remains
`retained-subject`; this derived presentation does not change v1 checkpoints.

After edits, bindings refresh from the new snapshot and actual after-images.
Old anchors become stale while their original quotes/revisions remain retained.
The callback captures `WorkingNotes.checkpoint()` through the caller's existing
episode owner; a capture failure stops effects rather than silently dropping it.
A trusted caller reconstructs the same scoped notes from authenticated source
receipts. Reconstruction restores no grants, consumed attempts or external effects.

The existing host-owned `FixedCheckPlan` may include strict mypy, public behavior,
syntax/style or other declared checks. The coding loop returns their actual
diagnostics and current source before another authorized model call. Unknown
effects, source drift and exhausted budgets remain terminal. No arbitrary
worker-authored command or test execution is introduced. Deterministic tests
exercise wrong return types and consumer failures followed by a bounded repair;
they establish feedback transport, not real-model accuracy.

## Role and evaluation boundaries

The independent reviewer retains its own notebook, read-only authority and strict
`submit_review_proposal` contract. It receives no coder-private conclusions.
Public checks and independent acceptance remain trusted host decisions; a model
recommendation or valid structured delivery cannot override them.

The prospective evaluation selects the existing unresolved Intake proposal
`cea1b3e7-bfa6-492a-b850-343a0c543878`, bounded to `source_relationships` direct-base
exposure, currently references-only. It does not close the broader map obligation.
Freeze exact source, public contracts, independent grading and budgets before
inference. Measure real calls, source acquisitions, authored notes and later use,
edit/check/repair outcomes, final correctness, custody, tokens, bytes and time.
One episode is diagnostic, not a causal estimate of improved coding accuracy.

Use the existing trusted local `CodingTask`, neutral process and canonical
Checkout owner. AGENTS permits that local development pathway without backlog
promotion, a native grant or terminal confirmation. Exact task authorization,
source/edit scope and budgets remain mandatory. Do not manufacture native slots
or replay consumed work. Local calibration grants have narrower read roots and
Tool names and do not silently authorize coding edits. No policy is broadened.

## Future switching economics

Do not switch models in this increment. A future qualified comparison must bind
provider identities and timestamps for idle/queue admission, original unload,
alternate load/readiness, role Context reconstruction/template measurement,
inference, alternate stop, original return/readiness and final Context restoration.
Separate cold/warm caches, failures, token counts and sampled RAM/GPU peaks.

Compare `unload + alternate load + inference + return load + Context restoration`
against the same task's resident inference/Context cost. Missing boundaries remain
unknown. The [historical comparison](../research/reviewer-model-comparison.md)
reports approximately 103 generated tokens/s for completed GPT-OSS calls and
retains lifecycle timestamps/logs, but not every phase's duration or a complete
switching break-even point. Do not substitute throughput for startup measurements.
