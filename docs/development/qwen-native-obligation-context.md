## Trusted frame and evidence contract

The explicitly selected frame binds the exact CodingTask digest, a named caller,
mandatory/helpful requirements, explicit queries, criteria and ALL-member/ANY-set
witness alternatives. Each witness names an existing authorized path, native
ContentIdentity, nonempty half-open character range, claim/reason and explicit
caller decision. The caller label is provenance, not authentication; the trusted
host selects the configuration. The model has no frame-creation/revision/approval
Tool and cannot remove requirements, expand source scope or supply its own verdict.

The host owns the semantic criterion-to-witness judgment. Reading a block can
activate an explicitly supported host judgment; it cannot turn an unjudged,
abstained or contradicted claim into support. Rank, filename and a model statement
are never satisfaction proof. Native grounding/association authenticates lineage;
it does not prove arbitrary prose true. All in-bound native global/query results
remain independent; no score fusion, role exclusion or new retrieval policy exists.

Readiness requires exact current native observations whose text is still present
in the selected active request. Partial ranges remain partial; adjacent actual
reads can combine. Compacted-away text cannot count. Status projection occurs
before faithful source-block rendering and tokenizer measurement, including the
existing measured-capacity reprojection path. Existing byte/token/time/call/action/
proposal limits are unchanged. Initial host metadata uses existing prompt-byte/
token accounting; native Tool/source counters retain their original meaning.

The assessment retains task/frame hash, repository/snapshot, criterion/caller,
current/expected source versions, explicit member dispositions, grounding resolver,
lexical lanes and actual Tool call IDs/ranges/text hashes. Its application content
hash identifies the projected assessment; it is not a new framework Evidence ID.
Per-turn/result records and separate immutable obligation-frame.json use existing
application persistence. They do not establish a restart protocol or durable
exactly-once task state.

Missing mandatory support refuses a proposal with CONTEXT_NOT_READY and correlated
unresolved feedback. That proposal consumes the existing allowance; existing
authorized reads can obtain evidence within the remaining budgets. Exhaustion
does not satisfy requirements. Helpful unresolved rows do not block. Contradiction
blocks its own conjunctive hypothesis; another explicit supported alternative can
still satisfy an obligation without eliminating the contradicted candidate.

Source is reauthenticated before requests and immediately before edit admission.
Changed required content is not silently rebound to an old host judgment.
Unchanged required resources are reauthenticated across admitted snapshot changes
and can support ordinary repair. A later check-only turn can show an old source
witness as stale while preserving the earlier READY edit_context_assessment that
admitted the edit. Readiness is explicitly before a source-changing action;
candidate tests, currentness, terminal completion, custody, review and publication
are separate claims. READY is not task correctness or exhaustive objective coverage.
