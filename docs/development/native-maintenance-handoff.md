# Supervised native maintenance handoff

Prospective [standing routine authority](routine-development-authority.md) may
now supply the trusted host callbacks below and issue fresh exact-task grants
without repeated operator prompts. Activation is separately authenticated;
historical manual grants, eligibility, acceptance and integration limits remain.

An explicit prospective [native Context profile](native-context-policy.md) now
connects larger independent request/read budgets, qualified token measurement,
automatic deterministic projection, pressure observations and existing precise
navigation. Packets without that versioned subrecord retain the strict profile
described below; no historical grant or consumed slot is upgraded.

Native coding now uses [aggregate source-read admission](aggregate-source-admission.md).
Oversized read batches receive correlated pre-entry refusals and can continue
with smaller authorized ranges. Final Tool feedback is retained in existing
bounded native capture even when no later model call consumed it. This does not
change native task/grant meanings, whole-owner readiness, the byte ceiling,
independent review or the consumed B-0049 slot. No live trial is launched here.

The subsequent [independent review actor](native-independent-review.md) adds
separately authorized model review and grounded proposals. The original manual
administrative review path described here remains supported.

[Diagnostic review](native-diagnostic-review.md) separately investigates archived
blocked native results. It cannot turn failure evidence into acceptance or create
an integration-eligible candidate; consumed coding dispatches remain consumed.

This delivery connects one reviewed backlog obligation to the neutral coding
process, independent candidate review and an authenticated, read-only integration
plan. It is repository administration under `WorkCycle.native`, implemented in
`scripts/backlog/native/`. It creates no new framework Agent hierarchy, coding
loop, coordinator, lock, scheduler or provider registry. B-0035 remains closed;
this slice does not close B-0043.

## Supported operator story

A trusted operator selects an existing reviewed BACKLOG item and a repair to one
existing `src/devtools/*.py` implementation file. Intake must authenticate its
current published approval and source resource. The supervisor supplies the
behavioral objective, public test files, separately preflighted private Python
acceptance, exact read addresses, information obligations, worker actor/source/
profile, portable settings and finite budgets. Native v1 supports the explicit
`current-whole-resource-v1` information criterion. It proves current text is
available for inspection; it does not prove the behavioral repair or exhaustive
task interpretation. General semantic decomposition is not implemented.

Prepare against an existing separate `feat/` branch at the administrative HEAD.
No worker branch is automatically selected or created. The same WorkCycle
one-assignment slot prevents replacing or replaying a legacy or native attempt.
Preparation records source/check identities and initial Context metadata, without
disclosing private acceptance to the worker or granting execution authority.

```text
uv run python -m scripts.backlog --root <root> native-prepare <B-number> --branch <feat/branch> --task <packet.json> --supervisor <actor-reference>
uv run python -m scripts.backlog --root <root> native-preview <B-number>
uv run python -m scripts.backlog --root <root> native-authorize <B-number> --reference <decision> --expires <ISO-time>
uv run python -m scripts.backlog --root <root> native-review <B-number> --reviewer <independent-actor> --reference <decision> --rationale <assessment> --decision accept
uv run python -m scripts.backlog --root <root> integration-plan <B-number> --review <review-sha256> --spec <integration-spec.json>
```

Authorization and review commands require genuine interactive host consent,
default No. Preparation and preview are not execution. Trusted Python hosts inject
an already selected `ModelInteraction` into
`await cycle.native.execute(item, interaction=worker, profile=profile,
authorize=current_host_decision)`. The callback sees the exact assignment and
grant; it must be a trusted host authority check, never a model response. There
is deliberately no CLI backend loader, automatic worker selection or permission
inferred from provider availability. No real model is invoked by the maintained
regressions.

## Packet and prospective records

`native.packet.validate` defines the closed task fields: `objective`, `source`,
`read_paths`, `tests`, `oracle`, `obligations`, `preflight`, `worker`, `settings`,
`budgets`, and `capture`. Capture must explicitly select `bounded-full-v1`.
Preflight retains supervisor comparison expectations and independent derivation
plus executable-control provenance. Evaluation checks finite comparison coverage;
the trusted supervisor remains responsible for the independence and correctness
of those controls. This is not automatic oracle certification.

The task is not serialized as the application-specific Qwen CodingTask. These
prospective records share WorkCycle's existing atomic writer and work-item folder:

| Record | Meaning |
| --- | --- |
| `backlog-native-assignment-v1` | Reviewed item, current source/input identities, complete task, supervisor, actual native Tool definitions and interpreter |
| `backlog-native-authorization-v1` | Exact assignment approval, current host principal, provenance and expiry |
| `backlog-native-dispatch-v1` | One claimed dispatch; not proof of provider or external effect entry |
| `backlog-native-observation-v1` | Bounded actual request/response, Tool/check intent or returned fact; exact immutable references |
| `backlog-native-execution-v1` | Known pre-release execution facts; cannot substitute for a released candidate result |
| `backlog-native-result-v1` | Known coding, usage, checks, private acceptance, candidate/diff, custody and uncertainty facts |
| `backlog-native-review-v1` | Independent host-approved decision bound to exact assignment/result/candidate evidence |

Native candidate and review readers retain original actor/source/profile
attribution. Legacy `backlog-qwen-*` schemas, task hashes, approvals and literal
review contracts remain unchanged. Native records cannot be read as legacy ones.
Hashes authenticate content correspondence under the trusted local writer; they
are not signatures or proof of a person's independence. Reviewer independence is
an explicit current host decision with distinct actor provenance.

## Execution, Context and custody

Native execution claims the existing Checkout before effects. The repository host
uses current SourceScope, Context source materialization and Localization frame
assessment. A model-selected read must provide each mandatory whole-resource
witness before edit admission. Each candidate snapshot receives a separate
assessment; old source support is not relabeled as current. Behavioral correctness
is decided by checks and independent review, never retrieval rank.

The shared `run_coding_agent` owns the only model/edit/check/repair loop. Actual
native Tool definitions and model settings must match the approved packet.
Automatic post-edit checks are reauthorized as well as explicit native calls.
Public checks use managed Commands in a fresh interpreter with exact repository
import roots. Final private acceptance runs before archival/restoration and is
never fed back to the coding worker. A public pass can coexist with private
acceptance failure; neither becomes an accepted candidate automatically.

Defaults are supplied explicitly by the host, within ceilings of eight model
requests, three proposals (at most two repair proposals), six acquisition actions,
120 seconds per call, 1,200 seconds coding/private-acceptance time, 32,768-byte
Prompt/resulting source and 1 MiB total native capture. Public/private output is
bounded to 16 KiB per channel; truncation cannot pass. Known-source reconciliation
still runs after timeout/expiry. Cancellation is not rollback or permission to
erase unknown bytes.

Declared source/public-test inputs, Tool schemas, interpreter/version, lock and
pytest configuration and relevant ancestor conftests are pinned. Configuration
identity checks do not grant worker read access to configuration. Full transitive
imports, installed dependency bytes, ignored settings and external services are
not claimed as complete environment closure. Private acceptance code and public
runner identities are retained and rechecked before invocation.

SourceCustody tracks expected before/after content. Checkout records admitted
after-images before writes. Known candidates are archived and restored.
Final candidate results are published only after Checkout release, binding the
authenticated release record. Release failure produces a blocked result even
when source custody and coding checks themselves succeeded. Unknown
source remains in place with Checkout ownership for existing default-No recovery;
the workflow does not remove that owner, retry an uncertain operation or issue a
replacement dispatch. Capture/serialization failure also blocks acceptance.

## Integration and authority separation

`Integration.candidate` has an explicit native reader branch.
`Integration.plan` reuses existing destination/source/ancestry checks and plan
formation. Native plans retain `candidate_kind: native-v1`, actual candidate
author, exact result/review/diff identities, checks and explicit remaining parent
obligations. The native maintenance path cannot declare parent completion.

The operator workflow stops at the plan. An independent integrator can separately
issue `integration-issue --native`, producing
`backlog-integration-native-grant-v1`. This first grant profile permits only
installation and validation, records the authenticated issuing host, and rejects
publication or parent-closeout allowances. Legacy integration grants cannot admit
native candidates. Installation uses the existing scope/reservation/Checkout
mechanisms and returns to the administrative branch. Broader native publication,
promotion and parent closeout require their own subsequent contract/authority
work; this slice does not silently reinterpret legacy publication attribution.

## Validation and remaining work

The maintained authored-repository scenario exercises operator preparation,
approval, two independent InteractionSource configurations, native source read,
wrong edit, real failing pytest, model-selected repair, real passing checks,
private acceptance, archival/restoration, independent review, authenticated plan,
refusal of a legacy grant, and installation with a fresh separate native grant.
Other scenarios cover expiry, source/configuration drift, tampered review and
candidate, incomplete information, exhausted budgets, capture failure, provider
uncertainty and preserved unknown source. They prove mechanics, not live-model
engineering competence.

Development uses the [maintained validation interface](validation.md): inspect
impact, select relevant native/host/Context/Tools/Checkout/legacy contracts, save
failures, then rerun the failed IDs and correction group. The final unchanged
protected profile remains mandatory for publication; no coverage or acceptance
policy is weakened. The [delivery receipt](../research/code-audit/native-maintenance-20261031.json)
retains exact commands, selections, elapsed times, final protected inputs and an
actual scripted episode through separately authorized installation.

The final protected validation executed once against executable commit
`a48b058f2abb1459b5cdade444cbbaa4801eebf3`: 3,987 passed, two skipped,
100% configured production line and branch coverage, 2,035.03 seconds including
command overhead. The maintained native scenarios contribute 21 tests. During
development, five failed scoped invocations retained their original results and
were diagnosed without restarting comprehensive validation. The 90-test impact
run took 358.72 seconds with 89 passes and one timeout-test assertion failure.
After correcting that assertion, five relevant uncertainty tests passed in
67.74 seconds. The observed duration difference is 290.98 seconds (about
4m 51s) versus repeating that broader selection; this is a counterfactual scope
comparison, not a controlled benchmark. The failed broader result remains failed;
the final protected result provides the complete successful validation.

Automatic planning/task selection, generic semantic obligation resolution, worker
routing, automatic reviewer routing, durable model restart and recovery,
standing grant migration and autonomous backlog closeout remain unimplemented.
The subsequent independent review actor consumes this exact candidate/evidence
subject under a separate finite role approval; see its linked contract above.
