## Reuse and ownership

Keep `resources.commands` in Resources: immutable Command, managed executor,
handles/events, output bounds, timeouts/cancellation and child cleanup are resource
mechanics. Execution still owns narrow Runtime/InteractionAttempt. Moving the
package to Execution fixes no demonstrated defect and would disturb established
dependencies. Existing ToolRunner and FixedCheckPlan/Tool/Result execute checks;
SourceScope, scoped source acquisition, RI occurrence/content identities and
Context range materialization remain authoritative. No second executor, registry,
workflow engine or memory/evidence database was introduced.

`tools.repository` owns typed Git inspection and the finite inspect/scope/select/
check/reinspect procedure. `observability.commands` owns selected factual
projections and deterministic diagnostic pattern summaries. The Codex-specific
available-event decoder stays under the external Agent adapter. Tools and Models
remain independent. See [contracts and dependency decision](command-capabilities.md).

## Actual capability and consumers

Git inspection authenticates the exact host root and committed revision, parses
literal porcelain-v1 NUL records into staged/worktree/untracked changes, rechecks
HEAD/status and refuses malformed/truncated observations. It uses optional-lock
suppression; real tests verify unchanged index bytes and no tree mutation.
Inspection is not an atomic content snapshot or sandbox. Ignored/submodule and
non-UTF8 filename limitations remain explicit. Native PATH/PATHEXT discovery
reports executable availability without installation, authorization or version
certification. Windows spaces, Unicode and special-character paths were exercised;
the portable argv design is not a native POSIX execution claim.

The host supplies immutable fixed Commands, revision, exact changed scope,
environment override-name allowances and deterministic check-selection rules.
Results distinguish passed/failed/skipped/refused/incomplete/cancelled; each check
retains known exit/duration/bounded diagnostics or original failure/unknown
acknowledgment. Earlier results survive partial execution. Cancellation propagates,
and potentially completed effects are never automatically repeated. One procedure
Tool instance/origin is one invocation. Host checkpoints, review, protected
validation, acceptance and publication remain separate.

Production entry points `scripts/check_change.py` and `scripts/command_patterns.py`
delegate the implementation. The first has finite operator profiles; its tests
profile calls the unchanged protected validator. Metadata JSON excludes arbitrary
command/env/output/error payloads. Native Model/Tool composition also executes
the procedure with host admission and original call-ID feedback; unauthorized
admission causes no command entry. Existing Qwen loops/checks and Codex invocation
were not changed or duplicated. The current authorized development host actually
used the shared procedure: one fixed whitespace check, 11 managed command
observations, passed, zero model calls. This is actual selected developer-agent
usage, not an inference about commands executed internally by Codex.

Three guarded independent hosts use real authored temporary repositories,
SourceScope/RI/Context exact-region acquisition and the same procedure. Qwen,
Codex, scripts and experiments imports and application-file access are denied.
Literal source `VALUE = 7\n`, content identity/span `[0, 10]`, staged/unstaged/
untracked paths, check output/exit and effect count are independently asserted.
The observed statuses were passed, failed and refused. The passing check executes
once; a nonapplicable second check is skipped. No model decides routine branches.

## Observation strength, privacy and procedural learning

Opt-in CommandInspector consumes the existing handle and preserves its original
result/error/cancellation, settling its owned collector. Known returned results
establish local completion; dropped/failed capture is qualified separately.
Interrupted fixed-check entry remains unknown when the existing Tool exposes no
handle. This is selected instrumentation, not complete automatic application
coverage or durable EvidenceSink ingestion.

Installed Codex 0.162.1 version/help and official documentation establish the
available JSONL surface. The optional bounded adapter reconciles selected
command_execution items, repeats, partial/out-of-order updates and contradictions.
Authored fixture observations were reported success and unknown; both process
entry and elapsed duration remain unknown. Default CodexAgent still exposes its
existing final response/usage interface, without a complete command feed. No
personal session discovery, paid call, live event stream or private-record scrape
was performed. [Official surface](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable).

Normalized observations contain curated family/operation, value-free argument
roles, selected capabilities, opaque host correlation and known/unknown facts.
Raw command/source/stdout/stderr/env/credentials are absent. Selected bounded
runtime diagnostics remain available only to the caller; caller retention and
nonprivate labels remain its responsibility. Synthetic private sentinels are
verified absent from analytics. Parsing or temporary digests alone are not a
privacy guarantee.

Pattern summaries deduplicate stable origins, count frequency/distinct origins
and success/failure/cancellation/unknown/conflict, retain known equivalent Tools,
and bound unordered co-occurrence suggestions. Captured capabilities are not
proof of command preconditions or safety; unestablished preconditions remain
unknown. Generic shell text stays opaque by default. No observed command becomes
trusted code automatically: promotion needs an explicit owner/contract,
independent tests and host authorization. Real selected development-host patterns
and separately labeled authored CLI patterns are in the receipt.
