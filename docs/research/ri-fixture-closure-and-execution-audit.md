## Actual task-to-mutation flow

1. Trusted host `CodingTask` fixes canonical source/test/read/new-source scope,
   baseline hashes, validation settings and model/action/proposal budgets.
   `scripts/qwen/coding_worker.run_local_task` is a bounded local developer entry;
   WorkCycle additionally requires an approved assignment/grant envelope.
   Checkout serializes mutation and restoration; possession of its owner is not
   independent task or publication authority.
2. `run_coding_task` authenticates inputs and prepares the scoped workspace. The
   selected interaction receives prepared Context or native ContextTools. Model
   calls propose operations; their schema and visibility grant no authority.
3. `ToolRunner.run` calls `validate` then `execute`, returning the executor's value
   or propagating error/cancellation. It has no generic task authorization, retry,
   deduplication or rollback. Domain tools and trusted callers own those controls.
   Runtime separately owns Conversation/interaction observation and checks response
   source; the application may call an interaction directly, but must preserve
   the same relevant protocol correspondence.
4. `ContextTools` authenticates source frame/current inputs and bounds disclosed
   paths/ranges. Native reads use existing Planning/materialization before exposing
   exact character ranges, versions and parent identities. UTF-8 truncation is
   bounded. Host source attestation is distinct from model-visible observation.
5. `edits` pure admission validates all proposed components: authorized paths,
   current source versions, observed spans/handles, overlap/duplicate bounds,
   exact absence for new files, byte limits and supported replacement syntax.
   This does not mutate files. Prepared replacement uses the existing literal
   anchor validator. LF/CRLF support and refusal of unsupported separators are
   intentionally narrower than general source indexing.
6. The application journals planned changes, calls the existing managed Git helper
   for all-patch `--check`, then one apply without `--reject`. This establishes
   preflight and all-component admission; it is not a general filesystem/crash
   transaction proof. Known expected source values can be restored after failure.
   Unknown bytes are preserved for explicit reconciliation, not overwritten.
7. Fixed host validation executes candidate Python. Commands use the maintained
   CommandExecutor. The stronger command/check-bundle path authenticates frozen
   tests/read/runners/config before and after checks and binds saved freshness
   receipts. Basic prepared `validate_workspace` does not use that complete guard.
   Scope-limited edit Tools do not make candidate execution an OS sandbox.
8. Correlated Tool call IDs, returns, journals and updated source feedback feed
   later scripted model turns. Worker acceptance, source restoration, unchanged
   immutable inputs, independent check PASS, review readiness and publication
   remain distinct claims. WorkCycle closeout requires `original_unchanged` and
   expected source/Git state before REVIEW_CANDIDATE; integration is still not
   authorized automatically.
