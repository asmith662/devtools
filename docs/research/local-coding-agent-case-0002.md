# Case 0002: independent source choice and correct shared-owner edit

One frozen real local-model attempt completed using the generalized framework.
Execution baseline `559ad49033e0d2389b68fa321cee870506e814aa`. All original
Case 0001 inputs, output, README/SUMMARY and collection manifest remain byte-for-byte
unchanged. The [case index](../../experiments/local_coding_dogfood/CASE-INDEX.md)
is a separate maintenance view, not an aggregate success-rate estimate.

The independently authored release catalog has 18 files and 11 permitted editable
runtime modules, with tests/docs/config read-only. No single correct file or
mandatory witness list was prescribed. Strict version ordering feeds catalog
selection and presentation, while policy, snapshots and interchange retain
distinct responsibilities. Before inference, the frozen focused suite had 4
failures among 7 tests and the held-out suite had 3 failures among 10. An independent
finite literal precedence-table reference passed all 7 and 10 tests before entry;
neither its code nor the hidden oracle was exposed to the model.

## Envelope, identity and usage

The existing Qwen3.8-27B UD-IQ4_XS llama.cpp service was READY with matching profile,
32K context, pinned image and native-host GGUF SHA-256. It was reused and left
READY, with no restart/download, paid fallback or substitution. Profile selection
is experimental configuration outside reusable Agents, not a Qwen dependency.
The actual coding process, RepositoryCodingHost, ModelInteraction/native Prompt,
Model/Tool composition, ToolRunner, RI/Context/scoped source, exact edit/custody,
fixed checks, repository procedure and managed Resources were used. Search and
listing are narrow host composition of existing APIs; no second index or loop.

Frozen limits: 6 requests, 3 proposals, at most 2 repairs subject to the shared call
budget, 16 acquisition actions, 4,096 output tokens/request, 28,160 measured input
tokens inside 32K, 180 seconds/request, 1,080 seconds in the process and 1,200 seconds
outer ceiling. Existing byte bounds remained unchanged. Actual: 5 inference
entries/responses, 10 acquisition actions, 1 edit. Usage: 24,137 input, 970 output,
25,107 total tokens; cache/write/reasoning counts unknown. Worker 60.225809s,
complete controlled evaluation 61.364488s. Seventeen selected command observations
and normalized patterns are retained separately from bounded synthetic diagnostics.

composition, scoped source, fixed checks/procedures, retrieval and Commands.
Ruff, supported formatting, configured strict mypy, layout, JSON/links, Intake and
whitespace checks pass; experiment host/support/oracle/verifier syntax/import

are unchanged. The full protected gate was not repeated, as explicitly requested;
all 923 previously validated physical inputs retain their hashes. Its historical
3,640 tests/two optional live skips/100% configured branch coverage remain prior
evidence, not a new run or experimental-coverage claim. Exact commands, timings,
identities and preservation are in the [machine receipt](code-audit/local-coding-agent-case-0002-20261028.json).

All 13 original forensic files, 903 RI rows, 68 Intake chains and historical refs
remain preserved. Original Case 0001 records and scientific history are unchanged.
No production defect or necessary contract correction was demonstrated; no
provider, orchestration, Evidence/recovery or Qwen enhancement was implemented.
Source Tool scope does not certify OS isolation of adversarial candidate Python.
This is one small-corpus observation, not general effectiveness, large-repository
discovery, causal retrieval benefit, provider portability or live repair proof.
Stochastic settings provide no identical-regeneration guarantee. A+C, observation
Option B, recovery and 188 historical RI-version obligations remain separate.

**Single next improvement:** put a bounded, complete authorized inventory into
initial Context using existing discovery metadata. The listing-only first request
cost one of six calls; avoiding it could leave more repair budget without raising

reads and grounded admission. This expected benefit needs a separately approved
increment and verification; no next increment has begun.
