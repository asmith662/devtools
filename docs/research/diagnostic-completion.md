## Supported correction through the existing owner

The [diagnostic review operation](../development/native-diagnostic-review.md)
now prepares prospective subjects with `native-diagnostic-finalization-v1`.
The exact approved subject binds one reserved model call. Existing historical
subjects and acceptance review retain their previous authority semantics.

Before each invocation, the bounded reviewer supplies a budget view identifying
remaining model calls (including the impending call), acquisitions, permitted
source Tools and current authorized resources. It explicitly identifies complete
historical baseline/candidate text already supplied in the subject. No confirming
reread is required. Current baseline identity does not authenticate an uninstalled
candidate, and other files are not the one implementation baseline.

The last approved call, or the next call after acquisitions are exhausted, offers
synthesis without source Tools. A one-call grant permits synthesis only. This
reserves an opportunity, not a successful model conclusion. No new call, invented
finding, automatic retry or lossy Context policy is introduced. Original requests,
responses and source disclosures remain captured. Expiry, source drift, malformed
output, capacity or uncertain effects can still block completion.

Refusals now distinguish per-response Tool batch size, total acquisition exhaustion
and unavailable Tools during finalization. Pre-entry refusals preserve actual
native call identities and state that no Tool effect entered. Existing completed
or uncertain Tool operations retain their original effect records.

The original B-0050 final response requested **one** read after both total
acquisitions were consumed. Its historical error text conflated those limits;
the original failed records were not edited or replayed.
