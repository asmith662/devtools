# Direct source investigation and multi-module coding

This is a bounded engineering comparison, not a scientific-controller run or a
claim of general proficiency. `manifest.json` freezes three genuinely new tasks,
their identities, host-owned acceptance and a cumulative six-run, 60-request,
5,400-worker-second ceiling before inference. There are no retry slots. Existing
bounded per-task repair is permitted. Confirmation is conditional on at least
one accepted development task without a source-integrity failure; it is run once
per harness after configuration selection. No tuning to confirmation outcomes.

Both conditions use the same pinned source, local Qwen profile, objective,
existing tests, independent oracle, Ruff/formatting and strict typing. Devtools
uses the existing direct local runner, Context/RI, ToolRunner, observed flat edits
and Checkout owner. Pi uses the pinned installed 1.3.0 SDK with scoped native
read/edit/write, scope listing and the identical fixed host validator. Neither
gets shell, cloud fallback or publication authority. Ten calls and 4,096 output
tokens/call remain fixed. Pi has 24 total Tool actions; Devtools has 24 read/check
actions plus three atomic proposals. This difference is recorded, not hidden.

Development objectives are a public regex split API in an authorized new module
with export updates, and coordinated BSD enum/detection support. Confirmation
is UUID-backed Identity construction. Read scopes include related modules and
distractors rather than prepared full-file disclosures. No implementation is
supplied in the prompt. Standard-library outputs are independent references;
runtime-review.json verifies the actual mock target before inference. No
disappearance/stat oracle or historical lazy task is reused.

## Evidence-supported diagnosis

Editing-06 initial lazy attempt passed a path as `expand_source.unit` and failed
on its first action. Its follow-up searched twice, then requested [0,1700) of a
1609-character source and an empty version for another file. The first refusal
returned bounds; the second schema error terminated the whole task. Neither
attempt disclosed source or reached editing. Read scope included every required
module/test; it was not an unavailable-file failure. Pi read five admitted files
directly, created the module, updated exports and repaired a typing-only import
failure. This does not prove Devtools Qwen was unable to implement the feature.

The previous direct adapter also incorrectly reported no truncation for a capped
prefix of a longer file. The corrected adapter requests the logical remainder
through existing bounded Context materialization and returns a truthful byte-
bounded span/continuation. Empty existing files are observable. New-file absence
uses the same inspect_source interface. The direct mode omits redundant legacy
read_source/inspect_new_source schemas, while historical/default mode retains
their contracts. Search, lookup and structural identities remain RI-owned.

Typed ContextRequestError distinguishes recoverable schema/unit/version/parent
mistakes from integrity, drift and authorization failures. The same worker
returns operation, schema, diagnostic and safe recovery guidance correlated to
the original native call, charging the action and continuing sibling calls.
Actual malformed provider JSON still belongs to ModelInteraction admission;
this change does not fabricate a valid ModelResponse or retry ambiguous calls.

Raw new evidence belongs under `.local/qwen-coding-worker/investigation-07/`.
Historical editing-06 records and all prior cohorts remain unchanged. Results,
limitations, exact candidate provenance and closeout will be recorded after
execution. No extra checkout or source-tree copy is created.
